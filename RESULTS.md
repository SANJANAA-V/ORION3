# ORION³ simulator results

Generated by `python orion3_sim_v3.py` (seed 42). Payments, accounts and campaigns are simulated; message text is real public data (scam messages from unseen templates, real casual legitimate SMS, and author-written formal legitimate notifications). Thresholds are chosen on the validation period and applied to the test period.

## Test PR-AUC

| Model | Easy | Hard |
|---|---|---|
| Rules (hand-set weights) | 0.277 | 0.018 |
| Message only | 0.262 | 0.141 |
| Sender behaviour only | 0.279 | 0.175 |
| Receiver network only | 0.591 | 0.215 |
| Behaviour + network | 0.898 | 0.383 |
| Fusion (behaviour + network + message) | 0.873 (95% CI 0.820 to 0.907) | 0.386 (95% CI 0.324 to 0.468) |

## Operating point (threshold at 1% false-positive rate on validation)

| Model | Easy recall / test FPR | Hard recall / test FPR |
|---|---|---|
| Behaviour + network | 0.889 / 0.0089 | 0.390 / 0.0085 |
| Fusion | 0.852 / 0.0038 | 0.412 / 0.0081 |

## Held-out scam family (impersonation)

Fusion PR-AUC 0.668 (easy), 0.253 (hard); recall at the validation threshold 0.688 / 0.351.

## Other findings

- Payments with no message: PR-AUC 0.883 (easy), 0.411 (hard).
- Legitimate fundraiser-style bursts wrongly flagged: 2.4% (easy), 3.1% (hard).
- The message signal does not improve on behaviour + network (differences are inside the confidence interval).
- Use the scoring time your own run prints (about 9 ms p50 and 15 ms p95 in my runs, models only).

## Limitations

- Synthetic payments. Real UPI behaviour will be harder.
- Formal legitimate messages are author-written from templates.
- The hard-mode validation period has few scams, and per-family test counts are small.
- Cost curve units are illustrative.
